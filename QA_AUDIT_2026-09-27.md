# Audit QA profond — EnerTchad
Date : 27 septembre 2026
Référence : branche `main`

## Périmètre

Audit statique du dépôt et contrôle de la production accessible :
- structure HTML, métadonnées SEO, hreflang et données structurées ;
- routes, sitemap, robots, redirects/rewrites Vercel ;
- JavaScript/CSS et syntaxe des principaux scripts ;
- formulaires et parcours de contact/recherche ;
- service worker et cache ;
- accessibilité déclarée et éléments vérifiables ;
- poids des ressources de la page d’accueil ;
- état de l’automatisation QA.

## Résultats

### PASS

- La page d’accueil possède un `<title>`, une description, un canonical, un H1 et des données JSON-LD.
- Les pages représentatives contrôlées (`contact`, `investisseurs`, `societe`, pôles, contenus éditoriaux) possèdent un H1 et un canonical cohérent.
- Les variantes FR/EN/AR contrôlées utilisent les bons attributs de langue ; l’arabe utilise `lang="ar"` et `dir="rtl"`.
- Les pages contrôlées utilisent les balises hreflang FR/EN/AR lorsque des équivalents existent.
- Le sitemap contient 206 URL uniques, dont l’accueil FR, l’accueil EN et l’accueil AR.
- Les 10 URL du sitemap qui ne correspondent pas directement à un fichier sont des routes propres appuyées par `index.html`, `cleanUrls` ou les rewrites Vercel.
- `robots.txt` autorise l’indexation et référence le sitemap.
- Les principaux scripts contrôlés passent une compilation JavaScript via `new Function()`.
- Les CSS contrôlés ont des accolades équilibrées ; les guillemets détectés comme ouverts dans certains gros CSS sont liés à des chaînes CSS/data et nécessitent un parseur CSS réel pour conclure.
- Le formulaire de contact utilise des `label`, `fieldset`, `legend`, états `hidden` et messages `role="alert"`.
- La recherche utilise un formulaire `role="search"` avec label associé.
- Le site déclare une stratégie d’accessibilité, un lien d’évitement, le support clavier et `prefers-reduced-motion`.
- Le CSP, HSTS, X-Content-Type-Options, Referrer-Policy et Permissions-Policy sont présents dans `vercel.json`.

### P1 — Performance

La homepage est très chargée :
- HTML : ~336 Ko ;
- CSS/JS/fonts référencés : ~867 Ko ;
- total source + ressources référencées : ~1,23 Mo, hors images réseau éventuelles ;
- environ 21 feuilles CSS sont chargées de manière bloquante ;
- 12 scripts sont référencés, dont 10 `defer` et 2 sans `defer`.

Les deux scripts non différés identifiés sont :
- `assets/chrome/u_cd226c00eb4b.js`
- `assets/chrome/u2_75a2c4383ddf.js`

Recommandation : faire une passe de réduction CSS par page, supprimer les feuilles historiques non nécessaires à l’accueil et différer les scripts non critiques après validation visuelle.

### P1 — QA automatisée

Le dépôt contient `.github/workflows/integrity.yml` et `scripts/check_integrity.py`. Le script contrôle les liens locaux, les IDs dupliqués et le JSON-LD.

Cependant, aucun workflow run n’a été exposé par l’intégration GitHub pour les commits contrôlés pendant cet audit. Le pipeline doit donc être considéré comme **présent mais non confirmé comme exécuté** dans cette session.

Recommandation : vérifier dans GitHub Actions que le workflow est activé et qu’un push sur `main` déclenche bien le contrôle.

### P1 — Formulaires

Le formulaire de contact et l’inscription newsletter utilisent `mailto:` pour ouvrir la messagerie du visiteur.

Conséquence : ce ne sont pas des soumissions serveur garanties. Leur fonctionnement dépend d’un client mail configuré sur l’appareil.

Recommandation : si une collecte fiable est souhaitée, connecter les formulaires à un endpoint sécurisé avec validation serveur, anti-spam et politique de conservation.

### P2 — Domaine canonique

Le dépôt contient un fichier `CNAME` indiquant `enertchad.td`, alors que les canonicals, le sitemap, robots et les données structurées utilisent actuellement `enertchad-delta.vercel.app`.

Il faut confirmer quel domaine est officiellement canonique en production. Si `enertchad.td` est le domaine public définitif, l’ensemble des URLs SEO devra être basculé de façon cohérente.

### P2 — Poids et architecture

La homepage concentre beaucoup de feuilles CSS historiques, composants et scripts provenant de plusieurs générations du design.

Recommandation : créer une architecture de bundles par famille de page :
- `core.css`
- `home.css`
- `poles.css`
- `journal.css`
- `tools.css`

et ne charger que le bundle nécessaire à chaque page.

## Limites de cet audit

- Le navigateur de cette session n’a pas permis de parcourir toutes les routes Vercel en temps réel ; plusieurs URL secondaires retournent un cache miss via l’outil web.
- Les contrôles de pixels, CLS/LCP/INP, Safari/iOS réel, Android Chrome réel, lecteur d’écran et axe-core en navigateur réel restent à effectuer dans une campagne E2E.
- Les liens externes n’ont pas tous été vérifiés par requête HTTP individuelle.
- Le script d’intégrité existant ne couvre pas les liens externes, les performances, les formulaires, les hreflang ni les ressources CSS.

## Plan de correction recommandé

1. Réduire le CSS homepage et supprimer les dépendances historiques inutilisées.
2. Différer les scripts non critiques.
3. Mettre en place une vraie soumission serveur pour contact/newsletter si nécessaire.
4. Confirmer le domaine canonique `enertchad.td` vs Vercel.
5. Ajouter un audit Lighthouse/axe E2E sur desktop + mobile.
6. Étendre `check_integrity.py` aux hreflang, sitemap, assets et formulaires.
7. Ajouter une vérification de liens externes et de statut HTTP dans CI.
8. Ajouter des tests smoke sur FR/EN/AR et les routes de chaque pôle.
