# Mobile QA and narrow bottom navigation

The live mobile review covered 16 selected public journeys at 320, 390 and 768 pixels across French, English and Arabic. No page-wide horizontal scrolling was observed, but at 320px the fixed quick-navigation menu extended to x=349, clipping Contact. Body overflow clipping hid the defect from document-width checks.

Give the five quick-navigation items equal available space and remove their intrinsic minimum widths. French investor/supplier labels use concise visual abbreviations below 520px while retaining full accessible names. Label font size remains 11px and touch areas are at least 48px high. All destinations and icons remain intact.

Local browser checks cover the English homepage, French/English contact and French publications at all three widths: all five targets remain inside the viewport. At 320px their rightmost edge is x=316, leaving the existing 4px inset. Three transformation tests and an export audit guard the shared markup and inline rules without an additional blocking request.

Functional review confirms mobile menu opening/expansion/Escape dismissal, investor menu dismissal, search and EOR result navigation, document filtering/reset, request preselection and French/English context switching. Empty required-field checks prevent sending and focus the first field once settled. No real enquiry was sent. This is desktop Chrome responsive viewport testing; physical iOS/Android devices, virtual keyboards and inbox delivery are not established by these checks.

The first hosted attempt was rejected by the performance budget because an extra stylesheet added 206 blocking requests across the compared pages. The responsive rules are now included in the existing page output, preserving the blocking-request count.
